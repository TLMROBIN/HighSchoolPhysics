日期：2026-09-21。核对版本：`ebc280f436705894e9ccbd0f9aeb17c830d4583e`。

本次是代码、部署现场与独立演示数据分析，不是已完成的浏览器视觉审计，也不是教学效果实验。未修改应用代码、运行配置和真实学生数据。

## 1. 结论与现场

项目已经具备题目版本、标签审核、测评发布、错题、重做证据与学习导航的基础。最大的改进空间是让诊断更可信、补救更具体、教师操作更容易，再用真实课堂数据检验效果。

本机、GitHub main 与远端 checkout 的 HEAD 一致。恢复脚本确认远端服务运行、HTTP 首页返回 200、自动更新计时器 active。runtime 检查仅为依赖可导入级别，不能据此声称 OCR/解析/PDF 等真实任务已经验收。

只读查询当前部署服务实际使用的 `data/school.sqlite3`：

| 项目 | 当前数量 |
| --- | ---: |
| 学生账号 | 841 |
| 教师账号 | 1 |
| 管理员账号 | 1 |
| 知识节点 | 158 |
| 题目 | 0 |
| 测评 | 0 |
| 重做记录 | 0 |
| 知识关系边 | 0 |

这些数字只描述该部署库，不代表其他系统、其他数据库或纸面材料没有题目和成绩。账号数量也不等于活跃人数。当前不能判断学生是否因此进步，首要产品目标应是让一个班级的一次真实测评完成教学闭环。

已核实的优点包括：发布时保留题目与标签快照；候选标签需教师确认；重做记录独立保存；学生端已有下一步建议、局部关系图、重做草稿保存及未作答禁止提交。新建议应延续这些基础。

## 2. 应先修正的可信度与流程问题

### 2.1 重做仍错，却被展示成已完成

独立内存数据库复现：发布演示测评 → 提交一道错题的重做 → 教师复核为 0 分。结果：

- `redo_status = reviewed`；
- 首页 `redo_queue` 不再包含该题；
- 导航模块仍认为它需要重做；
- 错题卡出现“本题重做已完成”。

证据：`repository.py:2761`、`:4027`、`:4200`；`server.py:869`、`:878`。

建议统一状态：待作答、待复核、需再练、待延迟验证、已巩固。未答对的题应回到补救任务，复核与学会必须分别表示。验收应覆盖首次做错、重做仍错、重做正确和延迟再测仍错四条路径。

### 2.2 一次答对即被判定已掌握

直接调用当前函数可得到 `classify_mastery(1, 1) == 已掌握`。按当前合并算法，一次原题答错加四次正确重做，正确率为 80%，也可以成为“已掌握”。这是规则计算复现，不是对真实学生行为的判断。

证据：`mastery.py:12`；`repository.py:2850`、`:2914`。

建议：保留原始作答统计，同时区分独立首次作答、看过解析后的原题重做、陌生变式和延迟检测。展示不同题目数、测评次数、最近证据日期、是否有提示，以及“证据不足”。同一道题多次重做不能作为多个独立能力证明。先采用透明规则，经校内样本校准后再考虑复杂模型；不要直接把任意固定题数门槛称为科学标准。

### 2.3 多选题重做控件与题型不一致

当前有选项的重做题统一渲染同名 `radio`，没有按多选题切换为复选框。后端批改支持 `multiple_choice`，前端却无法正常表达多个选项。

证据：`server.py:796–815`，`grading.py:30`。这是渲染实现确认，未做真机点击验证。

建议按题型使用单选、复选、数值与单位输入、过程作答区域，并统一答案序列化。验收至少包含一道单选、多选、数值题和主观题。

### 2.4 部分诊断百分比的分母不合适

`class_diagnostics` 里知识/能力标签按错题次数累加，却除以参加学生人数。同一知识点有多道题时，结果可能超过 100%。这不等于较新的所有掌握分析表都有问题，后者存在按尝试数计算的路径。

证据：`repository.py:3510–3545`。

建议区分“相关作答错误率”和“出现该错误的学生占比”，分别以相关有效作答数、有效参测学生数为分母，空白与缺考另外处理。例如 30 人各错同标签的 2 道题，60/30 是人均错题数 2，不能写成错误率 200%。

## 3. 五类功能的教学改进方向

| 功能 | 当前边界 | 建议升级 | 教学验收方式 |
| --- | --- | --- | --- |
| 知识诊断 | 主要从整题结果归因到所有标签 | 细化为可观察的学习目标；发现薄弱后用短探测题区分概念、适用条件和方法问题 | 教师能从结论回到具体作答证据，并允许确认或纠正 |
| 能力诊断 | 知识、能力、素养基本共用整题满分/非满分信号 | 按对象选择、受力图、过程划分、规律选择、列式、运算与检验采集评分点证据 | 不因末步算错而判定此前所有能力都差 |
| 题目分析 | 标签候选当前来自本地关键词规则 | 加入“考什么、在哪个步骤考、错误选项说明什么、适合何种补救”的结构化分析 | 每个关键标签有题干/评分点依据，教师可快速审核 |
| 错题集 | 原题查看和重做为主 | 错因确认 → 最小补救 → 原题或同构题 → 陌生变式 → 延迟再测 | 看陌生题独立表现和同类错误复发，不只看完成量 |
| 知识图谱 | 教材层级已具备，部署库尚无显式关系边 | 先建设一个单元的先修、易混、模型适用条件与典型错因关系 | 图谱能回答“先补哪一步、为什么、用什么题验证” |

能力与素养表述应克制：几道选择题可提供某项能力的局部证据，不能充分判定广泛的科学探究或科学态度表现。实验设计、证据评价等需要对应的任务、量规和教师观察。

物理示例：斜面问题结果错误，可能来自漏画摩擦力、投影错误、把合力写成某一个力，或者纯代数错误。系统应分别推送受力图补全、坐标投影练习、合力概念辨析或运算检查，而不是统一再练“牛顿第二定律”。未知错因先标为待确认，不仅凭错误答案自动断言。

核心标签候选调用当前仍是 `generate_candidate_tags()`，`llm.py` 标明 `rules-only`；无匹配时还会返回第一个标签作为低置信候选。配置了远程 Provider 并不证明这条业务链已经使用大模型。建议明确标示建议来源，对不确定项允许弃答，避免强行凑标签；升级模型后仍应保留教师审核与抽样质量评估。

知识图谱要先补内容：158 个教材层级节点不能等同于 158 个精细诊断目标；现有“前置”表结构也不能等同于已维护的前置关系。建议从牛顿运动定律等一个单元挑选约 10–20 个可观察学习目标，由教师审核少量有方向的先修关系。图谱只能提出“可能需要先检查……”并配探测题，不把关联当成因果。

## 4. 学生路径

建议主路径为：打开首页 → 开始今天一项任务 → 作答或选择卡住的位置 → 获得对应帮助 → 完成一道验证题 → 看见结果和下一次复习安排。

1. **首页找任务：已有基础，需增强。** 保留现有“先重做一道题”，增加简短推荐理由、预计时间、完成标准；从待办中选少量任务，避免把未学内容和所有历史错题同时压给学生。
2. **理解题目与作答：需补题型和过程支持。** 重点支持物理图像、清晰公式、草稿/过程照片或触笔输入。当前学生错题卡主要按纯文本渲染；不能仅因数据里预留了 media 就认为图文题体验已完成。
3. **不会时获得帮助：需新增分层支持。** “我卡在理解题意/受力分析/列式/计算”比单一“看解析”更有诊断价值。提示分层展开，记录是否使用提示，后续用未见题独立验证。
4. **重做与等待反馈：存在已复现断点。** 待复核题应显示教师反馈状态；复核仍错后有明确“再试一次/先补这个知识”的出口。
5. **结束与再次回来：需要调度。** 展示本次完成了什么、还待验证什么、何时复习。将“我觉得会了”的自评与系统证据并列，避免自评覆盖客观判断。

继续保留已有草稿功能；进一步验证断网重试、防重复提交、返回位置恢复、共用平板上的账号隔离。上述增强尚未经过 Android WebView 真机验证。维持既有路线图约束：不改登录过期策略、不依赖扫码或地址栏；跨系统帮助需要携带题目上下文并能回到原任务。

## 5. 教师路径

建议主路径为：选班级/测评 → 导入试卷及作答 → 处理少量异常 → 发布诊断 → 讲评/分组补救 → 查看再测效果。

1. **首次使用：门槛高。** 当前空状态有下一步入口，但题目与组卷仍需 JSON。改为试卷文件上传或成绩模板导入、可视化题目列表、题型选项、标签搜索勾选，默认继承班级和测评上下文。
2. **日常批改：需围绕异常工作。** 按“识别不确定、评分有争议、标签待确认、重做待复核”建立可直接点开的队列；原图/学生过程、判分依据和操作并列。例行客观题可按明确规则自动反馈，有歧义再进入人工队列。
3. **错因与重做复核：目前需填 ID。** 从学生作答直接标错因和反馈；支持同题连续复核、批量应用并预览影响。教师不应寻找或复制记录 ID。
4. **选择班级与测评：需显式入口。** 当前教师 dashboard 与页面主要采用 `assessments[0]`。增加清晰切换器，避免教师需要改 URL 或填测评 ID。
5. **看完诊断后：需要直接行动。** 每条发现提供受影响学生、证据题、建议讲解活动，以及创建短练习的入口。按错因和所需支架临时分组，同一学生可在不同主题进入不同组，避免固化“优中差”。
6. **课堂使用：增加只读讲评模式。** 展示题干、匿名选项分布、典型错误推理、分步讲解和出口题，不展示学生姓名及管理表单。

教师端可以在成熟后提供跨测评趋势，但应先统一不同卷子、难度和评分口径。历史总正确率上涨不能直接解释为教学有效。

## 6. 与既有路线图衔接及建议顺序

既有 `TEACHING_UX_ROADMAP.md` 的八项方向总体仍有价值，但其中现状描述已经部分过时：学生已有下一步卡；SSO 已有后续变更；部署库前置关系尚未填充。此次不覆盖原路线图，以下作为更新建议。

| 顺序 | 建议范围 | 完成标准 |
| --- | --- | --- |
| P0 | 重做状态断点、多选控件、诊断分母、证据不足提示 | 完整走通不同题型和错误分支；没有误报完成及失真的百分比 |
| P1 | 教师无 JSON 主流程、真实试卷导入、班级/测评切换、异常复核队列 | 一位教师无需工程协助完成一个班一次测评 |
| P2 | 一个单元的评分点、错因、最小补救、同构/变式题与延迟再测 | 学生完成帮助后能用新的独立题验证，教师看得见未解决问题 |
| P3 | 局部先修图谱、课堂讲评模式、进步记录 | 图谱与报表能直接进入具体教学动作 |
| P4 | StudyAgent/edusimu 上下文联动与更复杂诊断模型 | 先证明前序流程可用、题库质量足够，再验证跨系统任务与返回路径 |

不建议在题库为空时优先投入复杂自适应算法或全学科大图谱。先收集真实题目、可解释的作答证据和教师修正，才有依据决定算法该升级到什么程度。

## 7. 如何检验是否真正改善教学

建议选一个班、一个单元试行 2–4 周。以下是试点设计建议，不是既有效果证明，也不把此规模当成因果研究。

- 学习：未见过的同目标题独立正确率；延迟再测表现；同类错因复发比例。原题重做正确率另列。
- 诊断：教师抽查的结论吻合情况、错因修正情况、证据不足占比；先找系统性误判。
- 学生使用：从进入系统到第一次有效作答的时间、任务完成率、失败后恢复率。
- 教师负担：导入到发布的操作时间、每份作答人工复核时间、需要求助的步骤。
- 对比口径：前后题目应同目标且难度相近，记录提示使用与缺考；若需要判断干预贡献，可进一步采用匹配班级或交错实施，控制基础差异与重复练习效应。

研究依据：IES/WWC 的《Organizing Instruction and Study to Improve Student Learning》支持间隔学习、例题与独立练习交替、通过测验主动提取，以及解释性提问。它为这些设计方向提供依据，但不证明本项目有效，也不规定适合所有物理知识点的固定 1/3/7/15 天排期。

来源：https://ies.ed.gov/ncee/wwc/PracticeGuide/1 （本次已读取，指南发布于 2007 年）。
