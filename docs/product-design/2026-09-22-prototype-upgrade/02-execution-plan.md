## 阶段 B：完成这次周测的最小导入链路

**2026-09-22实际材料补充：** 本卷15题100分；8—10题全对6分、选对但不全3分；11/12题包含表达式、文字与电路绘图，13—15题需分步人工评分。13班98页，14班52页且页序反向，13班第54/71页倒置。必须支持整理副本中的旋转、页序调整与学生映射确认，不把候选相邻页直接绑定学生。第1题答案冲突等应在冻结测评快照前解决，详见 [本次材料核对](05-this-exam-preflight.md)。这些是现有导入任务的具体要求，不新增细分诊断或AI批改依赖。

不先建通用智能阅卷平台。围绕用户现有试题、标准答案与扫描答题卡完成：

1. 试题与答案合并校对：题号、题型、满分、图文内容、标准答案/评分标准、知识/能力标签。可在本地协助整理一次再导入，避免一开始就做复杂排版编辑器。
2. 提供简单导入预览，保留原卷/图形和逐题定位；公式或图片不能完整转为文本时使用原题图，不能丢图后声称题目完整。界面可预览原件，常规用户无需填写 JSON。
3. 扫描件与学生学号、页码对应。合并 PDF 必须生成映射清单；不能仅靠页序或文件序号认定学生。
4. 优先接入已有逐题得分/客观答案表；没有时完成小样本人工或辅助识别，产出同一格式。学生过程不作细分能力分析。
5. 主观题按现有评分标准记录教师已确认分数，不要求教师新增错因标签。只有总分不足以生成逐题错题本。
6. 确认 5–10 份跨不同作答情况的小样本，校对分数、身份与题号，再处理全班。小样本在隔离实例或未发布预览内验证，避免发布成不完整正式考试。
7. 教师预览确认后一次性发布。保存该批题目、身份映射、复核结果、导入批次与发布时间记录。

如果只有扫描图而无已判分数据，最小目标是“可查看原图并逐题录入或导入人工评分”。视觉 AI 可另做可选试点，但不为它搭建全套自动诊断。没有评分来源就不能凭扫描件存在自动生成成绩。

技术复用：`create_question / confirm_question_tags / assemble_paper / create_assessment_from_paper / import_ocr_responses` 等现有领域方法。补齐评分确认与发布边界，避免另写一套直改数据库的导入器。图像身份归属、题号缺失等错误先在预览报告中解决。

## 阶段 C：轻量复习与师生体验适配

### 学生

首页只突出“今天到期的少量题”。每题说明“第几次验证、上次结果、下一次日期”。已有草稿保留；新增多选草稿恢复、失败重试去重、完成后下一题。页面状态使用“本次正确/需再练/待教师确认/本题已巩固”。

阅读解析、学习练习、正式验证是用途差异，不扩展成多套复杂功能。正式验证默认收起答案，打开本题完整解析后切为学习练习并清楚提示不增加验证进度。无法证明学生在系统外未看答案，不把这一机制包装成严格考试监考。

自主重做仍错时提供“再看解析/请老师帮助”，不要求学生选一套专业错因。知识/能力导航保留关联题入口，不加探测题。

### 教师

首页提供四个日常入口：导入周测、待确认作答、查看本次统计、查看复习进度。删除普通工作流中的记录 ID、JSON 和 Phase 编号。标签建议可批量确认，低匹配允许留空待处理，不能强制接受规则默认标签。

客观题按已确认规则自动判，主观题按班级/题号连续复核。反馈非必填；无须每次填写诊断。教师看到“多少人待复核、多少题到期、多少题三次通过”，不会把三次复习规则变成三倍手动点击负担。

课堂讲评、自动分组与跨系统联动不列为首次周测前的强制任务。可先用现有打印导出和题目查看。学生端沿用 Android WebView 的使用条件，不依赖地址栏、扫码，不更改已约定的登录会话时长。

## 数据与规则设计约束

- 保留原测快照、原作答、重做记录和复核历史，不能为新规则清空 `data/`。
- 复习只新增必要元数据：尝试用途/是否独立、幂等提交标识、巩固进度/下一次时间、规则版本。进度可以从既有事件加新字段推导，避免重复存多套相互矛盾状态。
- 发布评分结果与导入确认使用真实状态，不把 OCR 置信度冒充教师确认状态。
- 三次验证按提交时间计算；状态变更与评分修订可重放，重复复核不加次数。
- 旧记录缺乏独立性或间隔信息时继续保留历史统计，不把旧 `done` 无条件迁移为三次通过。
- 图谱、错题列表与报表从同一快照标签口径读取；当前错题富化仍有读取当前题库标签的路径，实施统计修正时需一并对齐。
- 首次版本以整数分为现状；若本次评分细则有 0.5 分，必须先支持无截断存储与导入，不能静默取整。是否需要以实际试卷为准。

## 验收清单

### 规则与数据

- [ ] 一次原测正确：显示本次正确，标签不判已掌握。
- [ ] 错题三次按间隔正确：3/3；同日三次正确不能直接3/3。
- [ ] 对、对、错：当前进度清零；历史两个正确和一次错误都保留。
- [ ] 重做待复核不会消失，复核仍错回到需再练。
- [ ] 网络重复请求、重复复核不重复计数；分数改判后统计和排期一致。
- [ ] 单选、多选全对/漏选/错选、填空与主观题分别按本卷规则处理。
- [ ] 缺考/缺页/识别不清不会被写成零分或空白；真正空白单独计数。
- [ ] 测评错误率与复习统计分开；所有百分比不超100%；零分母不伪造0%。

### 首次使用与体验

- [ ] 空库开始能录题、确认标签、组卷、选班、建测评，不依赖样例 ID。
- [ ] 样本姓名/学号/页码/题号一致，原图与结果能相互定位。
- [ ] 部分得分按原评分标准保留；实际周测总分与逐题和一致。
- [ ] 教师预览确认后发布；发布前学生不可见，发布后学生仅见自己的结果。
- [ ] 学生完成一次重做，教师或规则确认后，首页、错题卡、图谱一致。
- [ ] Android WebView 实测输入、多选、草稿、断网恢复、返回原位置；本轮尚未完成该验收。

## 发布与完成条件

实施时先使用独立测试库验证，不触碰生产 `data/school.sqlite3`。按项目约定运行本地相关测试和 `VERIFY_TARGET=local bash scripts/hsp_release_check.sh`，完成适当的页面验证，再按发布流程同步；最后运行 `REQUIRE_REMOTE_HEAD_MATCH=1 bash scripts/hsp_release_check.sh`。全部通过后才声称远端已验证。涉及真实资料导入，应另有实际材料清单、教师评分确认与发布记录，不能仅以代码部署成功当作首次使用完成。
