## 2. 参考项目的取舍

Learning Commons 提供教育数据图模型与访问方式；不是可直接替换本系统的物理诊断应用。

- [仓库](https://github.com/learning-commons-org/knowledge-graph)：连接课程标准、课程、学习科学资料；数据可用于关系数据库、图数据库或本地处理，无需预先引入专门图数据库。
- [Learning components](https://docs.learningcommons.org/knowledge-graph/schema-reference/learning-components)：借鉴细粒度学习目标、稳定标识和来源字段。我国高中物理条目由本项目教材、课程标准和教师审核建立，不能直接照搬现有数学 / ELA 数据。
- [Learning progressions](https://docs.learningcommons.org/knowledge-graph/schema-reference/learning-progressions)：`buildsTowards` 表示有助于后续学习，不等于严格先修；`relatesTo` 表示有关联，不暗示先后或依赖。
- [Eedi Misconceptions Graph](https://docs.learningcommons.org/knowledge-graph/datasets/learning-components/eedi-misconceptions-graph)：借鉴“共同误解影响多个学习目标”的结构。其数据属于数学，且当前通过 Eedi constructs 连接，不能假设已经与高中物理节点对齐。

首期只借鉴结构和方法，不导入外部数据集、不调用外部服务分析学生。以后引入内容时逐数据集核对适用范围与许可。

## 3. 一张共享关系图，叠加个人证据

公共图谱保存学科关系；个人图层保存作答、诊断假设和验证结果。同一道学科连线不会因为某个学生做错题而改变。

### 节点

1. 教材导航节点：保留现有册、章、节及稳定 ID。
2. 学习目标节点：在节下增加可观察动作，如“辨认研究对象所受的力”“判断静摩擦力方向”“沿选定方向列牛顿第二定律”。不能把整节标签直接等同于细粒度证据。
3. 能力节点：受力分析、方程建立、模型建构等，连接多个章节。
4. 素养节点：保留物理观念、科学思维、科学探究、科学态度与责任。展示活动证据与覆盖，避免仅凭选择题给整个素养打掌握分。
5. 后续扩展：典型模型、常见误解、实验任务、课程标准条目、复习资源。题目及小问作为证据入口，默认不把所有题目铺满星图。

### 关系

| 关系 | 方向与语义 | 例子 / 使用限制 |
| --- | --- | --- |
| 包含 | 父 → 子；目录结构 | 册 → 章 → 节 → 学习目标；不用于错误传播 |
| 严格先修 | 基础 → 目标；须有具体教学依据 | 只在明确学习目标上审核，单独检验无环 |
| 学习支撑 | 基础 → 后续；有助学习 | 力的合成与分解 → 牛顿第二定律的应用；不强制锁课 |
| 关联 / 易混 | 对称关系；不表达因果 | 平衡力与相互作用力等概念比较 |
| 迁移 | 来源情境 → 目标情境 | 动力学方法 → 带电粒子运动；标明具体条件 |
| 运用能力 | 学习目标 / 任务 → 能力 | 动力学任务 → 受力分析 |
| 支持素养 | 能力 / 活动 → 素养要素 | 模型建构任务 → 科学思维中的模型建构 |
| 妨碍理解 | 误解 → 学习目标 | “运动需要合力维持”妨碍理解牛顿第一定律 |
| 考查 / 证据 | 题目小问 → 目标；作答 → 证据 | 标明直接考查、辅助涉及和教师复核状态 |

每条正式边必须有语义类型、方向、理由、来源定位、审核人、审核状态、适用条件和图谱版本。AI 仅生成候选；同题标签共现只能生成关联候选，不能自动认定先修或因果。知识 / 能力 / 素养维持不同类型，即使名称相似也不合并。

## 4. 薄弱区域怎样形成

输出分三层：**直接证据 → 区域假设 → 诊断验证**。第一版采用可解释规则，阈值写入算法版本，经教师抽查后再校准，不声称已具有测量效度。

1. 只取学生本人、已发布且纳入测评的有效证据。排除待确认、缺考、未纳入和已撤销结果。
2. 考试首次作答、未见答案的独立验证、学习练习、自评分开计算。原题反复重做不能当成多道独立题；同题多标签也不重复扩大区域样本数。
3. 从不同题目中有错误证据的目标产生候选，再沿教师审核过的学习支撑、迁移或能力关系寻找共同区域。章、册、泛化素养等高连接度节点不参与扩散，限制邻接深度，避免整张图连成一个红团。
4. 多标签综合题判错，只能证明这道题未完成，不能证明所有标签都薄弱。区域候选显示支持题目、相反证据、覆盖情况和尚缺的诊断证据。
5. 共同能力与共同误解标为“待诊断”。通过选择项错因、小问步骤、教师复核或少量有针对性的独立新题区分：概念错误、建模困难、运算失误、未完成。
6. 为区域给出学习入口与验证路径：回看必要基础 → 对比 / 诊断任务 → 新情境独立验证。验证结果只更新有证据覆盖的部分，不能自动把相邻节点全部变绿。

建议第一版区域卡包含：区域名称、涉及目标、不同题目数、跨情境覆盖、直接证据、待验证原因、先做什么、判断更新日期。不用一个混合正确率充当“掌握概率”。证据不足时明确显示“尚未观察 / 待补测”。

例如，斜面、连接体、带电粒子题都出错时，可以提出“受力分析与动力学建模”候选区域；必须进一步检查错误步骤或诊断题，才能区别受力遗漏、列式困难与其他原因。示例不代表当前任一学生的真实诊断。

## 5. 学生和教师的使用方式

- 学生默认看到与近期困难相关的局部星图和 1—3 个待处理区域；全局总览按主题收起，缩放后逐级展开。
- 形状区分知识、能力、素养；颜色与文字共同表达有错误证据、待诊断、近期答对、尚无证据。近期答对不直接标成整个知识点已掌握。
- 点击节点可看定义、上下游关系、连线理由和本人题目证据；点击区域展示可能的共同困难及验证任务。
- 教师可审核关系、比较班级共同困难、查看自己教学范围内的学生证据。保留列表模式、键盘操作和手机 / 平板布局。
- 素养以多次任务、实验过程和观察证据呈现；科学态度与责任尤其不能由几道客观题推断。

## 6. 与当前系统的接入路径

首期继续使用 Python、SQLite 和现有身份权限。158 个导航节点及少量扩展目标无需因为“图谱”名称迁移数据库。

建议通过新增表逐步扩展：

- `learning_graph_nodes`：统一类型索引，映射现有知识、能力、素养 ID；新增细粒度目标和误解节点。历史标签仍引用原 ID。
- `learning_graph_edges`：跨类型语义关系及来源、方向、适用条件、草稿 / 审核状态、版本；旧知识边可通过适配读入。审核与发布应生成不可变版本。
- `graph_evidence_bindings`：将题目版本 / 小问 / 特定选项映射到学习目标，记录标注理由和复核状态；支持旧标签的候选映射。
- `student_region_diagnostics`：保存图谱版本、算法版本、输入证据标识 / 指纹、候选区域和解释；可重算，能回溯旧结论。

不要把新目标批量补写进已发布 `tag_snapshot_json`，也不要改写 `student_responses.initial_answer`。旧证据通过明确版本的映射进入新分析；标签拆分只生成待复核映射，不把旧节级证据平均分摊到所有新目标。

代码落点：新增图谱查询及诊断服务模块；在 `student_learning.py:graph()` 接入；前端使用现有静态资源机制和 SVG / Canvas；教师端增加关系审核入口；将新增表纳入迁移、备份、恢复和权限检查。API 应按当前用户校验学校、班级与学生范围，不接收任意学生 ID 后直接返回数据。

## 7. 三个交付阶段与验收

| 阶段 | 范围 | 验收重点 |
| --- | --- | --- |
| A 关系图谱 | 先以力学试点，沿用全学科目录；建设经审核的目标与关系、节点详情及列表模式 | 每条连线说得清；方向正确；不把目录当语义；无证据节点不被判弱 |
| B 区域诊断 | 接入真实作答、证据分层、候选区域和定向验证 | 多标签题不全点判错；重复题不增独立样本；可查看支持与反证；区域结果可复算 |
| C 学习闭环 | 诊断任务、跨情境迁移验证、教师班级区域视图、逐步扩展全学科 | 能从区域进入适当任务并返回更新；改善有新证据；教师确认建议具有教学价值 |

必要验收样例：

1. 只有一道综合错题：显示相关目标待排查，不给出确定共同错因。
2. 多道不同情境题指向同一能力：形成待诊断区域，并保留各题的其他解释。
3. 学生基础题近期答对、应用题错：保留相反证据，不沿图盲目向基础传播错误。
4. 同题重做十次：不同题目数仍为一；看解析后的练习不计作独立验证。
5. 未测、缺考、待确认：不进入错误率分母，不上薄弱颜色。
6. 图谱版本升级：原卷答案、标签快照、首次作答和旧报告仍可追溯。
7. 学生与教师权限隔离；手机、平板、桌面与列表模式均可读可操作。
8. 开发完成后执行相应自动化测试、真实账号浏览器验收及 `REQUIRE_REMOTE_HEAD_MATCH=1 bash scripts/hsp_release_check.sh`；未通过不能称远端已验证。

当前交付仅为本方案和使用真实节点名称、拟议连线及虚构作答状态的交互示意。没有修改业务代码或生产数据，没有发布图谱功能。

交互示意验收：JavaScript 语法检查通过；浏览器实际核对 736px 与 320px 布局，节点选择能更新关系与证据说明，“知识关系 / 薄弱区域示例”切换有效，浏览器错误日志为空。这些只证明示意交互可用，不证明真实学生诊断有效。


## 2026-10-07 阶段 1、2 实现范围

- 保留 158 个知识、15 个能力和 18 个素养节点，新增 92 个可观察学习目标，绑定现有 23 张诊断卡的全部检查点。绑定核对题目内容指纹和检查问题，重复补齐不产生新版本。
- 276 条目标归属、能力和素养联系，加上 23 条逐项编写教学依据与适用条件的语义联系（含 6 条跨题方法迁移、相关或混淆关系）。系统整理初版显示虚线和待教师确认，绝不伪造教师审核身份；目录连接只解释层级。
- 学生工作台默认恢复知识图谱，局部星图最多同时展示中心和 12 个邻居，完整目录可搜索访问；列表模式、键盘、触控、节点定义、连线依据和个人诊断观察均可用。观察仅为本步通过、借助帮助、待检查或尚未观察。
- 教师工作台新增诊断与知识图谱模块，逐步修订问题、选项、答案、提示和具体目标，确认、排除或新增关系，保存即形成不可改写的新发布版本。必要前置仅限具体目标，拒绝循环。
- 实际存储使用学校隔离的 learning_graph_releases：每版完整保存目标、边、诊断卡及绑定，避免首版多表拼接导致半发布；原有目录 ID、题目内容、首次作答及已发布快照不改写。新诊断开始时同时固定卡片、目标和发布 ID，已有会话继续使用原卡片。
- 后续模型预处理自动生成目标审核候选，教师未确认前不展示猜测的目标和连线；模型配置仍仅管理员可设置。
- 本阶段不启用跨题薄弱区域推断、前置错误传导、知识点整体掌握标记或自动推荐学习路径。

操作入口：学生“我的学习 → 知识图谱”；教师“工作台 → 诊断与知识图谱”。先逐题查看卡片与映射，再确认或修订关系；已有学生诊断不会被重新解释。
