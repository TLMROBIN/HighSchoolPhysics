# 高中物理知识图谱与错题闭环系统完整蓝图

## Summary

建设一个部署在局域网服务器上的高中物理教学系统，学生通过 Android WebView 套壳 App 在平板访问，教师和管理员可通过平板或电脑访问。

系统核心是“知识图谱 + 能力标签 + 题库资产 + 试卷批改 + 错题闭环 + 班级诊断”。

首期不追求全自动智能推荐，而是先跑通：

```text
测评批次创建
-> 试卷/题目录入
-> AI 候选标注
-> 教师审核
-> 答题卡与学生身份绑定
-> 答题卡识别
-> 低置信复核
-> 客观题批改
-> 错题本生成
-> 学生掌握标记
-> 教师统计诊断
```

## Product Scope

- 单校自用，不做多校租户系统。
- 支持学生、教师、管理员三类角色。
- 支持多层级知识点、物理学科能力标签、知识点双向语义链接。
- 支持题库、试卷、答题卡扫描、客观题自动批改、错题本、批量打印导出。
- 支持 LLM API Key 接入，用于题目知识点标签、能力标签、错因分析等候选生成。
- 支持未来接入统一身份认证平台，但首期仍内置本地账号体系。
- 首期虽为单校自用，所有核心数据仍需带有学校/组织范围字段，避免未来接入统一平台或多校扩展时重做权限模型。

## MVP Definition And Cut Line

首期 MVP 必须抵抗“完整平台”诱惑，只保留能验证教学闭环的主链路。

MVP 必须保留：

- 本地账号、班级、教师授课范围和学生平板 WebView 持久登录。
- 一张试卷或一次作业作为测评批次，能绑定班级、学生、题目和答案。
- 选择题自动批改，填空题只支持数值精确匹配或简单容差匹配。
- 题目与知识点/能力标签的 LLM 候选标注，以及教师审核确认。
- 个人错题本、学生掌握标记、教师按班级导出 A4 错题本。

MVP 应延后：

- 全局知识图谱的复杂可视化、自动推理和自动语义链接。
- MinerU API 与本地部署的复杂混合调度；首期可先固定一种主解析路径。
- 文字型填空、复杂等价表达式、大题过程评分的全自动批改。
- 多维能力画像、自动掌握度算法和个性化推荐题。
- StudyAgent、edudimu 等系统的真实 SSO 联调。

MVP 验收重点：

- 一个班级的一次真实测评能从答题卡识别到错题本导出完整跑通。
- 答题卡学生身份绑定无错绑，选择题识别和批改有人工复核兜底。
- 教师能在考后较短时间内获得可打印的个人错题本和班级错题统计。
- 新题 LLM 候选标注必须可审核、可修改、可追溯。

## Knowledge And Ability System

- 知识点体系暂不一次性定死，先设计为可版本化、可编辑、可合并拆分的四级结构。
- 知识点来源采用“三源合一”：课标/教材目录作为规范底座，组卷网知识点树作为实战颗粒度参考，教师教学经验作为校本修订层。
- 组卷网采集仅用于登录后提取知识点目录和筛选树，不批量抓取题目、答案、解析等版权内容。
- 能力体系暂以“普通高中物理课程标准 + 中国高考评价体系 + 物理学科命题论文”为来源，由教师进一步查证后定稿。
- 能力标签应回答“学生完成这道题需要什么思维动作”，不同于知识点的“这道题考什么内容”。
- 能力标签可先预留：信息提取、情境建模、受力分析、过程划分、模型建构、临界条件、守恒思想、图像转化、方程建立、数学运算、实验设计、数据处理、误差分析、推理论证、情境迁移等。
- 知识点、能力标签和题目标签都必须有稳定 ID、版本号、启用状态、软删除状态和变更记录。
- 知识点合并、拆分、改名不应破坏历史错题本和历史统计；历史数据引用当时版本快照，当前图谱只影响后续分析。
- 知识图谱本体需要版本化，版本内容包括知识点、能力标签、图谱关系、节点层级、别名和启用状态。
- 掌握度推断若从手动标记升级为算法判断，算法版本、输入数据版本和图谱本体版本必须一起记录。
- 图谱本体或掌握度算法升级后，系统应支持按新版本重算诊断结果，同时保留旧版本诊断结论以便解释历史报告。

## Assessment Sessions And Snapshots

- 系统必须把每次考试、周测、单元测、周末作业或重做任务抽象为 `AssessmentSession`。
- 测评批次记录学期、年级、班级、时间、来源、满分、参与学生、试卷、答题卡模板、批改状态和统计状态。
- 答题卡、批改结果、错题、掌握标记和班级统计都必须归属到某个测评批次。
- 测评批次内保存题目快照、答案快照、标签快照和评分规则快照，避免题库后续修改影响历史结果。
- 测评批次内还应保存知识图谱本体版本和掌握度推断版本，避免后续知识体系变化导致历史诊断不可解释。
- 测评批次支持状态流转：草稿、待识别、待复核、已批改、已发布、已归档。
- 已发布或已归档的测评批次不能静默修改；若需要修正，必须产生改分或修订记录。

## Graph Design

- 知识图谱节点包括知识点、物理模型、实验主题、方法思想。
- 节点支持层级、别名、说明、教材范围、启用状态、来源。
- 节点之间支持语义化双向关系：前置、关联、易混、共现、迁移、包含、同类模型。
- 学生端只展示和本人错题、掌握程度相关的局部图谱。
- 教师端展示完整图谱，并可按章节、班级、学生、知识点、能力标签、错题频率筛选。
- 图谱必须配合列表/表格视图，避免只有视觉效果而不可操作。

## Question Bank And Tagging

- 每道题作为独立题目资产入库。
- 题目字段包括：题目 ID、题干、选项、答案、解析、题型、来源、年级、章节、难度、图片/公式、适用场景、质量状态、备注。
- 标签字段包括：知识点标签、能力标签、物理模型标签、错因标签、易错题标签。
- LLM 只生成候选标签、置信度和依据说明。
- AI 结果默认进入“待审核”，教师确认后才成为正式标签。
- 同一道题的 LLM 标注结果要缓存，避免重复消耗额度。
- 标签体系要支持版本号，防止后续知识点体系调整时历史数据无法追溯。
- 单题知识点标签数量需要有上限，避免多标签污染统计；超出上限时进入教师确认队列。
- 题目修改需要保留版本历史；已进入测评批次的题目不能被当前题库修改静默覆盖。
- 物理公式、图像、电路图、受力图应保存原图或统一格式，错题导出和在线展示必须共用同一渲染来源。

## LLM Integration

- API Key 由管理员统一配置，教师不可查看 Key。
- Key 只保存在后端，并加密存储。
- 支持多个 Provider，例如 OpenAI、DeepSeek、通义、豆包、硅基流动等。
- 支持连接测试、启用/停用、调用统计、额度提醒、失败重试。
- Prompt 模板分为知识点标注、能力标注、错因分析、解析质量检查、题目拆分辅助。
- 向 LLM 发送题目内容和必要上下文，不发送学生姓名、班级、成绩等个人隐私信息。
- 所有 LLM 输出均作为候选建议，不直接写入正式题库或学生画像。
- Prompt 模板和模型版本必须记录到每次候选标注结果中，便于回溯和批量重标注。
- 新模型或新 Prompt 上线前，用一批人工标注样题做一致性评估，未达标不替换默认配置。
- LLM 调用需要有成本上限、调用统计、失败降级和 Key 轮换策略。
- 同一题目出现模型候选、教师审核、历史标签冲突时，以教师确认结果为准，并保留冲突记录。

## Document Parsing

- 建立统一文档解析中心。
- 图片和答题卡识别使用 PaddleOCR。
- Word 文件识别使用 Microsoft MarkItDown。
- PDF 文件识别使用 MinerU。
- MinerU 采用混合策略：默认使用 API，额度不足、网络异常、隐私敏感或大批量任务时切换本地部署或后台排队。
- 解析输出统一中间格式：页码、题号、题干、选项、答案区、图片、公式、坐标、置信度。
- 低置信度区域进入教师复核。
- 文档解析后进入题目拆分、清洗、LLM 候选标注、教师审核、正式入库流程。
- 文档解析结果需要版本化保存，包括原始文件、解析工具、工具版本、解析时间和人工修订记录。
- Word/PDF 解析后的题号、选项、图片、公式和表格必须经过结构校验，异常项进入复核队列。
- 对同一文档重复解析时，应保留差异对比，避免覆盖教师已经修订过的题目。

## Exam And Grading

- 支持试卷录入、答案录入、答题卡模板管理、扫描批次管理。
- 选择题和填空题作为首期自动批改范围。
- 大题首期只录入得分、人工错因和教师备注，不做全自动评分。
- 答题卡识别结果需要保留原始图片、识别框、置信度、人工修正记录。
- 批改结果生成学生作答记录，并自动关联题目知识点、能力标签和错题本。
- 对低置信识别、答案冲突、缺考、空白、异常涂卡等情况进入复核队列。
- 答题卡必须可靠绑定学生身份，优先使用学号、二维码、座位号或准考证号中的稳定标识；绑定冲突必须人工确认。
- 自动批改需要独立的判分规则引擎，规则随测评批次保存快照。
- 填空题首期仅支持精确匹配、数值容差、多标准答案等可解释规则；单位、有效数字、等价表达式和文字答案先进入人工复核或后续版本。
- 教师可以覆盖批改结果，但必须记录修改前后值、原因、操作者和时间。
- 支持学生或教师发起复核/申诉流程，复核结果进入审计日志。

## Wrong Question Workflow

- 错题本以学生为中心，关联考试、题目、错误答案、正确答案、标签、错因、重做记录。
- 学生可以对错题和知识点标记掌握程度。
- 掌握程度建议使用简单等级：未掌握、基本掌握、已掌握、需教师讲解。
- 教师可按班级、学生、知识点、能力标签、考试、掌握程度筛选错题。
- 支持批量导出打印版错题本。
- 打印版支持：只题目、题目+答案、题目+解析、按学生分页、按知识点分组、按能力标签分组。
- 首期推荐策略以“原题重做”为主；题库积累足够后再做同标签推荐题。
- 掌握程度首期以学生手动标记和重做结果为主，不提前引入复杂自动掌握度模型。
- 后续若引入自动掌握度，需要明确定义输入、近因衰减、难度权重、状态流转和可解释说明。
- 错题本导出必须端到端验证公式、图片、电路图、受力图和分页效果，避免在线能看、打印变形。
- 导出模板应支持按学生分页、合并重复错题、隐藏答案、附答案页、附解析页等常用教学场景。

## User And Identity

- 首期内置本地账号系统。
- 支持学生、教师、管理员角色。
- 支持 Excel/CSV 批量导入学生、教师、班级。
- 学生字段至少包括姓名、学号、班级、入学届别、状态。
- 教师字段至少包括姓名、账号、任教班级、角色。
- 默认密码采用“系统生成临时密码 + 首次登录强制修改”。
- 教师可重置本班学生密码，管理员可重置所有用户密码。
- 用户导入、禁用、重置密码、角色变更都写入审计日志。
- 为未来统一认证预留 `identity_accounts` 绑定表，支持 `provider`、`issuer`、`subject`、`external_id` 等字段。
- 登录身份与业务角色分离，未来可接入 StudyAgent、edudimu 等系统的统一身份平台。
- 用户主键使用系统生成的稳定 UUID，不使用姓名、学号、手机号或外部账号作为主键。
- 身份认证与业务权限分离；本地账号只是首个认证 Provider，未来可增加统一身份 Provider。
- 预留 `auth_provider_config`，用于保存外部认证提供方的名称、端点、客户端配置、启用状态和密钥密文。
- 教师数据范围必须和任教班级、学科、角色绑定；默认只能查看自己负责的班级和学生。
- 共享平板场景必须支持显式退出登录、会话过期和敏感操作重新确认，避免上一名学生的会话被下一名学生继续使用。

## Access Control And Privacy Compliance

- 权限模型必须采用“主体-资源-操作”矩阵，而不仅是页面级角色判断。
- 主体包括学生、教师、管理员、未来外部身份用户和系统任务。
- 资源包括学生个人信息、作答记录、错题本、掌握标记、班级统计、题库、试卷、测评批次、导出文件和系统配置。
- 操作包括查看、创建、修改、删除、导出、批改、复核、发布、重置密码和管理 Key。
- 学生只能查看自己的错题、掌握标记和已发布给自己的测评结果。
- 教师默认只能查看自己任教班级的数据；跨班级、跨年级查看必须有显式授权。
- 管理员可以管理用户、班级、系统配置和审计，但敏感数据导出仍需记录用途和操作者。
- 所有业务表应预留学校/组织范围字段，首期固定为单校，未来统一平台或多校扩展时不重做数据隔离。
- 未成年人隐私需要按最小必要原则采集，学生姓名、学号、班级、作答、错题和掌握度均视为敏感教育数据。
- 系统应记录隐私告知和监护人/学校授权依据，至少支持按学校管理要求登记授权来源。
- 学生毕业、转学、退学或超过保留期限后，应支持数据归档、脱敏或删除策略。
- 备份、导出、LLM 调用和日志留存都必须遵守同一数据保留与删除策略。

## Android App And Deployment

- 后端部署在局域网服务器上。
- 学生通过 Android WebView 套壳 App 访问，不直接使用浏览器。
- App 实现方式参考 `/Users/binyu/Projects/StudyAgentApp`。
- App 需要支持 Cookie、DOM Storage、文件选择、拍照上传、返回键处理、局域网 HTTP 或 HTTPS 访问。
- 登录状态由后端 HttpOnly Cookie 和长效 refresh session 维护。
- App 启动后访问 `/app` 或 `/dashboard`，由后端判断是否已登录，避免每次进入登录页。
- 启动地址不应硬编码在业务逻辑中，至少用构建配置集中管理；后续可考虑服务器地址配置或局域网服务发现。
- 若局域网可配置 HTTPS，优先使用 HTTPS；若暂时使用 HTTP，必须限制服务器白名单。
- App 不保存 LLM Key，不保存学生敏感数据明文。
- App 不保存密码，也不在原生层保存 refresh token；会话持久化主要交给后端 HttpOnly Cookie 和 WebView Cookie 存储。
- WebView 应禁用不必要的本地文件访问能力，仅允许必要的文件选择、拍照上传和白名单内主框架导航。
- 生产环境不全局忽略 SSL 错误；如测试自签证书，只允许测试配置下的指定域名例外。
- App 销毁时正确停止加载并释放 WebView，避免依赖不可靠的手动垃圾回收技巧。
- 文件上传沿用 Photo Picker、TakePicture 和 FileProvider 路线，不申请 `MANAGE_EXTERNAL_STORAGE` 等过宽权限。

## UI Design

- 学生端平板优先，界面像 App，不像后台系统。
- 学生首页只保留高频入口：我的错题本、待重做、知识点掌握、最近考试。
- 学生图谱只显示个人相关局部图谱，避免全局大图造成干扰。
- 教师端强调高密度管理：题库、试卷、错题、班级诊断、知识图谱、解析任务。
- 教师图谱旁必须有筛选器和表格列表。
- 管理员端保持朴素：用户、班级、权限、LLM Key、解析任务、审计日志。
- 打印导出模块单独设计，A4 版式优先，不受屏幕 UI 限制。
- 整体视觉风格应安静、清晰、适合反复使用，不做营销式首页。
- 学生端采用底部导航，入口控制在错题本、待重做、知识掌握、最近考试四类以内。
- 学生错题卡片应支持快速掌握标记、查看解析、重做记录对比，减少深层跳转。
- 教师端同一批题目至少支持表格视图和预览视图；表格视图负责批量筛选、批量审核和导出。
- LLM 候选标签审核界面要展示建议标签、置信度、依据说明和一键确认/编辑/删除操作。
- 班级诊断看板优先展示高频错题、知识点错误率、学生分布和待处理复核任务，不优先做炫目的大屏。
- 后台解析、批改、导出等长任务必须有队列状态、失败原因、重试入口和完成提醒。

## Data Governance And Operations

- 多年题库、错题、考试和学生掌握记录是核心资产，必须支持定时备份、异机副本和恢复演练。
- 支持完整数据导出，至少包含题库、知识点、标签、测评批次、作答记录、错题本和用户班级关系，避免单校系统形成数据锁死。
- 所有关键操作需要审计：用户导入、登录失败、权限变更、标签审核、批改修正、题目删除、错题导出、LLM Key 变更。
- 关键后台任务需要可观测指标：文档解析成功率、OCR 低置信比例、人工复核量、LLM 标签采纳率、批改修正率、导出失败率。
- 系统升级需要有数据库迁移、回滚方案和版本说明；已归档测评数据必须在升级后可回放和可校验。
- 单校局域网部署仍需考虑服务器单点故障，至少提供手动备份下载和恢复流程。

## Phased Roadmap

- Phase 1：系统底座  
  本地账号、班级、角色、权限、Android WebView 访问、持久登录、测评批次骨架、基础审计和备份。
- Phase 2：题库和知识体系  
  知识点管理、能力标签管理、组卷网目录采集辅助、题目录入、LLM 候选标注、教师审核。
- Phase 3：文档解析和试卷录入  
  PaddleOCR、MarkItDown、MinerU 混合解析，题目拆分，试卷和答案管理。
- Phase 4：答题卡识别和客观题批改  
  答题卡模板、扫描批次、学生身份绑定、客观题自动批改、判分规则、复核队列。
- Phase 5：错题本和打印导出  
  学生错题本、掌握标记、教师筛选、批量 PDF 导出。
- Phase 6：图谱和班级诊断  
  Obsidian 式知识图谱、学生局部图谱、班级知识点/能力统计。
- Phase 7：试卷质量和推荐  
  正确率、区分度、标签覆盖、试卷质量分析、同标签推荐题。
- Phase 8：统一平台接入  
  将本系统与 StudyAgent、edudimu 等项目对接统一身份认证。

## Acceptance Scenarios

- 教师创建一个测评批次，绑定班级、试卷、答题卡模板、题目快照和答案快照。
- 教师创建四级知识点，并添加“前置/易混/迁移”关系，教师端图谱和列表都能正确展示。
- 教师从组卷网登录页面采集知识点目录作为候选树，并人工确认后写入系统。
- 上传 Word 试卷后，MarkItDown 解析出题目 Markdown，并进入题目拆分流程。
- 上传 PDF 试卷后，MinerU API 解析失败时任务可切换到本地 MinerU 或排队重试。
- 上传答题卡扫描件后，PaddleOCR 识别学生信息和客观题答案，低置信结果进入复核。
- 学生身份绑定冲突时，系统阻止批改发布并要求教师人工确认。
- 一道题经 LLM 生成候选知识点和能力标签，教师修改确认后才正式入库。
- 教师修改批改结果时，系统保留原始识别值、原始判分结果、修改原因和操作者。
- 学生登录 App 后关闭再打开，不需要重复登录。
- 共享平板上学生显式退出后，下一名学生不能看到上一名学生错题本。
- 学生查看个人错题本并标记掌握程度，教师能按班级和知识点查看统计。
- 教师批量导出某班错题本，PDF 按学生分页并适合 A4 打印。
- 管理员批量导入学生账号，生成临时密码，首次登录强制修改。
- 管理员查看用户导入、密码重置、标签审核、批改修正、错题导出等审计记录。
- 教师尝试查看非任教班级学生错题时，系统按权限规则拒绝并记录审计。
- 学生毕业或转出后，管理员可以按策略归档、脱敏或删除其个人数据。
- 知识图谱本体调整后，历史测评仍能按旧版本解释，且可按新版本重算诊断结果。
- 管理员可完成一次备份导出，并能在测试环境恢复关键数据。
- 未来统一认证启用后，本地用户可以绑定外部身份，业务角色不受登录方式变化影响。
