# HighSchoolPhysics 升级开发方案：可信作答、结果复核与学习闭环

日期：2026-10-01。状态：**第一批工程核心已实施并发布；课堂验收、扫描和填空增强继续按门禁推进**。详见[实施与验收记录](2026-10-01-response-evidence-implementation.md)。

## 1. 升级结论

在现有“题库—测评—首次作答—错题—间隔复习”基础上，统一学生作答的输入和证据，分离答案提取、结果判定、学习分析，形成可核对、可纠错、可扩展的教学闭环。

近期顺序为：**补齐作答证据和双来源导入 → 建立发布后纠错 → 跑通真实班级使用 → 接入选择题答题卡 → 增强实验填空判定**。主观题先作为后续内容与纸面复习能力，不在本轮恢复分数或自动评分。

成功标准是教师能解释每条结果的来源，学生能可靠地完成复习，系统错误能够撤销其对错题和统计的影响。识别速度、模型数量和图谱复杂度不作为单独完成标准。

### 2.4 延续的产品约束

1. 当前正式范围仍为选择题、实验填空；不录入总分、排名、主观题得分。
2. `correct / wrong / blank / pending` 分开；缺失是覆盖状态，不等于 blank；缺考、不纳入者不制造错题。
3. 多选集合完全一致才正确；漏选不记半对或部分分。
4. 首次答案、原始证据、测评题目与标签快照冻结，重做不能覆盖。
5. 看过系统内答案后的当日练习不增加独立验证进度。沿用次日、再隔 3 天、再隔 7 天的机制，第三次有效正确称“本题已巩固”。
6. 未确认识别和判定不能进入学生错题或正式统计；不把 AI 自报置信度当真实准确率。
7. 不改变会话有效期；学生端适配既有 Android WebView，不依赖扫码、新开浏览器或手输地址。

## 3. 目标流程与模块职责

```text
已发布题目内容/测评快照 ────────────────┐
                                      ↓
CSV / 人工录入 / 外部结果 / 扫描件 → 身份与题项映射
                                      ↓
                              作答证据与提取记录
                                      ↓
                         规则判定 / 外部判定核验
                                      ↓
                         异常与冲突复核 → 发布
                                      ↓
                      有效作答 → 错题 → 独立验证
                                      ↓
                           时间序列与教师教学行动
```

### A. 答案提取（Extraction）

只回答“学生写了什么”。输出原始资源、页码、题区、原始文本、标准化文本、提取方式、识别版本和可解释异常。不得因为识别不清而返回学生答错。

身份匹配单独判定：优先使用学号/账号等稳定标识；姓名只能辅助，重名和跨班冲突进入人工复核。整页身份未确认时阻断该页全部作答；不把猜测绑定到学生。

### B. 结果判定（Decision）

读取测评快照和已确认答案规则，返回结果、理由码、使用的规则/答案版本、判定方法。待确认答案或缺失规则一律返回 pending。教师可以确认外部结论或更正系统结果，但必须保留前后值与理由。

### C. 学习分析（Learning evidence）

只读取已发布有效判定及已确认的练习事件，区分首次、独立验证、学习练习。错误只证明该题本次表现；与题目关联的标签属于观察维度，不自动认定每个标签都未掌握。

**技术形态：继续使用现有 Python 应用、SQLite 和后台任务基础。** 当前规模下无需为了这三个职责拆微服务、引入 Redis 或另建向量数据库。

## 4. 双来源输入与统一协议

### 4.1 教师入口

“考试与作答”保留现有入口，增加三种明确选择：

- **导入学生答案**：CSV 或粘贴表格，系统按冻结答案规则判定。
- **导入已核对结果**：同时接收学生答案和外部结果，明确来源及复核依据。
- **上传答题卡**：第二阶段开放，只支持经过标定的选择题模板。

CSV 为首批必做；Excel 可另存 CSV 使用。直接 `.xlsx` 读取作为增强项，在没有文件解析实现及验收前不宣传已支持。外部 API 首批完成协议及服务层，开放第三方凭据接入安排在后续。

### 4.2 内部记录建议

每条记录映射到 `assessment_id + student_id + snapshot_id`，而非仅用题库题号。教师界面显示“原卷题号/小问 + 录入序号”，下载模板预填映射，禁止按输入行顺序猜题。

| 字段组 | 建议字段及规则 |
| --- | --- |
| 批次 | schema_version、batch_key、payload_hash、source_type、source_name、created_by |
| 目标 | school_id、assessment_id、student_id、snapshot_id；学校身份从授权上下文取得，不能信任上传字段 |
| 答案 | answer_presence=`present/blank/unknown`、raw_answer、normalized_answer；null/缺列代表未知，确认空白单独声明 |
| 证据 | source_asset_id、page_number、bbox、source_row、file_hash；CSV 记录行号，扫描记录页与题区 |
| 提取 | extraction_method、extractor_version、extraction_confidence（可空）、review_reasons |
| 外部结论 | supplied_outcome、source_system、external_record_id、reviewed_by/source_reviewer、reason |
| 判定 | proposed_outcome、effective_outcome、method、rule_version、answer_version、reason_code、decision_id |

其中 source_reviewer 是外部声明，不能冒充本系统认证的 reviewed_by。人工输入没有识别模型置信度，应为空；“已人工确认”用独立状态表示，不伪造 1.0。规则确定也不表示图像识别可靠。

兼容旧 CSV 的 `学生,题号,作答,结果`：通过映射层转换，导入页声明来源；原始列和上传文本仍可追溯。空答案但声称“正确”的行进入异常，不自动记空白或补造答案。

### 4.3 外部结果采用矩阵

| 情况 | 建议处理 |
| --- | --- |
| 有已确认答案，无外部结果 | 按规则判断；填空无法确定则 pending |
| 外部结果与规则一致 | 保存双重依据；满足批次来源确认后可纳入发布 |
| 外部结果与规则冲突 | 进入 conflict，展示原答、标准答案及两种结论；教师确认前不可发布 |
| 填空语义规则无法确定，但外部已人工核对 | 保留外部依据，由本系统教师确认采纳；支持预览后一批确认，无须重输每条答案 |
| 只有外部结果，没有原始答案 | 保存为来源不完整候选；不虚构答案；补录或按明确的历史兼容规则处理，首批默认阻断发布 |
| 外部给出分数或部分分 | 不进入学习判定字段，不自动换算对错；需提供当前无分数口径的结果 |
| 未识别、重名、重复题号、错模板 | 阻断对应批次/记录，明确修复入口 |

“可信来源”是身份、版本和复核过程可追溯，不是文件自报可信。即使来源已登记，客观规则冲突仍需处理。

### 4.4 预览、提交与重试

预览逐条显示原答案、规范化答案、建议结果、外部结果、冲突、缺失和题号映射，汇总纳入人数×题项覆盖。提交绑定批次 hash、参测名单版本、测评快照版本；预览后任何相关内容改变都要求重新预览。

同批次同内容重复请求返回同结果；同 key 不同内容报冲突。同一学生同一题的重复行不能静默覆盖。发布前再次执行完整性和权限检查，使用事务防止并发发布产生重复错题。解析错误返回行号和原因，默认整批不写入，避免一半成功难以核对。

## 5. 数据设计与发布后纠错

### 5.1 增量结构

以下为逻辑表建议，施工前确认现有迁移账本和最新 schema，不在本方案硬编码下一版本号。

| 对象 | 内容 | 与现有结构的关系 |
| --- | --- | --- |
| response_import_batches | 来源、hash、预览版本、状态、统计、操作者 | 通用输入批次；scan_batches 作为扫描专用扩展关联 |
| response_evidence | 原答、资源/行定位、提取版本、识别置信度、时间 | 追加保存，关联 student_responses；历史缺项明确 legacy/unknown |
| response_decisions | 规则/外部/人工结论、理由、版本、操作人、被替代 decision | 追加判定流水；initial_answer 不覆盖 |
| response_review_items | 身份、识别、规则冲突等类别，状态、处理结论 | 可复用既有复核字段作为投影，新增统一任务索引 |
| response_publications | 本次发布/修订版本、有效判定集合、影响数量 | 固定统计计算所用版本，避免发布与重算不同步 |

`student_responses` 保留兼容查询及首次答案；增加有效判定指针或统一查询视图。所有新统计、错题和复习入口统一读取 effective response 投影，不能有页面仍读旧 outcome、另一个页面读修订结果。

所有证据引用必须校验同学校、同测评、学生范围和资源授权。现有题目唯一性约束先保留：首批仍禁止同一测评重复放入同一个 question_id；若将来支持重复题位，另做约束迁移，不声称仅新增 snapshot_id 就已解决。

### 5.2 状态与门禁

批次：`draft → validated → needs_review/ready → published`，失败、取消可重试，不能穿越复核门禁。

待确认原因分开：identity、extraction、answer_rule、external_conflict。outcome 只有 correct/wrong/blank/pending；错误原因、任务执行状态不得混用为学习结果。

发布必要条件：身份和题项映射正确；纳入学生覆盖齐全；无待确认/冲突；答案规则已确认或有明确人工判定依据；证据引用可访问。缺考与不纳入单列展示。

### 5.3 发布后修订

新增“更正作答/结果”入口，不能用再次导入代替：

1. 教师选择具体记录，查看原始证据与全部历史，填写“识别错误/标准答案错误/外部结果错误/身份错误”等原因。
2. 生成修订预览：受影响作答、错题、统计、复习安排；多人答案规则变化必须逐项列出范围。
3. 原首次答案、原快照、原判定保留；追加更正答案与判定事件，发布后页面同时展示“首次记录”和“经更正的有效记录”。
4. 同事务更新有效指针和发布版本；统计、错题投影可幂等重建。耗时重算未完成时显示处理中，不展示混合版本数据。
5. 原错题误判为错：标记撤销来源，停止该来源的到期任务；保留历史练习。如同题仍有其他有效错误来源，不错误移除全部复习任务。
6. 原正确改为错误：增加有效错误来源，建议从修订生效次日安排复习，不能把历史时间回填成学生已经逾期；历史时间和修订生效时间都保留。
7. 标准答案改动产生新规则版本；原题目快照不重写。历史重做如需按新规则重判，先列出影响、经教师确认后追加事件，不能静默回算。
8. 身份错误默认阻断普通更正入口，交由有权限人员核对影响；不得把已产生的个人学习记录直接整体挪给另一学生。

当前 `learning.progress()` 按原始事件回放。实施时必须同时调整其有效事件来源与修订时间语义，不能只改数据库 outcome 就称纠错闭环完成。

## 6. 分题型建设

### 6.1 选择题：第一优先级

保持单选/多选集合匹配，增加合法选项集合校验、标准答案缺失阻断、非法字符与单选多涂异常。标准化仅做大小写、合法分隔符和顺序处理，不把未知字符猜成选项。

扫描阶段先支持一种学校实际使用的固定答题卡：模板版本、定位点、页尺寸、题区、选项位置均登记。流程为上传原件、质量检测、模板识别、页面校正、身份映射、题区切割、OMR 填涂识别、复核、规则判定。

不将整张卡交给大模型直接输出错题。手写选择答案、任意版式、缺页与不匹配模板先人工转录或暂不支持。保留原图及裁剪坐标，教师可从任意结果返回证据。

### 6.2 复核队列

优先展示身份不明、模板不匹配、单选多涂、擦改、模糊、低置信度和外部冲突；界面提供“原图题区—识别答案—标准答案—建议结果”并排核对。支持键盘与批量导航；确认必须针对真实可见记录，不批量掩盖未读取内容。

不能只复核低置信度：试点期对自动通过项作分层随机抽检，覆盖不同页面和题号。发现整页偏移、身份错绑或模板问题时，冻结相关批次扩大复核。模型高置信也可能系统性错位。

重复上传按文件 hash 和业务键检查；后台任务支持取消、限时、重启恢复与幂等。复用 document worker 的任务治理经验，但答题卡资源、输出协议和权限与原卷导题分开。

### 6.3 实验填空：第二轮能力增强

分三层处理：

1. **文本与数值标准化**：空白、全半角、允许的数学格式、分数/小数；保留原文。
2. **题目规则**：答案别名、绝对/相对容差、单位量纲及换算、单位是否必填、有效数字要求、变量定义和表达式适用域。每个空独立配置，复用整题公共条件。
3. **AI 辅助**：仅对规则无法判定的语义答案提出建议、依据与不确定项，交教师确认。超时/缺 Provider 返回 pending，不返回 wrong。

物理边界：`10 m/s` 与 `36 km/h` 可在该题允许换算时等价；`10 m` 不等价；`-10 m/s` 不能忽略负号；数值接近但精度不符合要求不能默认正确。不能全局删除单位、正负号、上下标或矢量信息。

表达式用受限解析器，禁止 eval 和任意代码；带根式、分母、变量范围的等价判断需要领域限制。无法证明等价继续 pending，不用“看起来像”判错。

### 6.4 主观题：明确后置

后续可增加 `practice_mode=online_choice/online_fill/paper/photo_review` 等能力描述，并保存完整题目、原作答、教师反馈与纸面学习单。主观题正确性若不在当前结果模型覆盖范围内，应显示“待教师反馈”，不强塞二值结果。

拍照重做、分步能力证据、rubric AI 辅助作为独立后续阶段。恢复分数或自动评分须形成新的产品范围决策，不随本次升级默认启用。

## 7. 学生与教师体验

学生沿用“今日到期练习—独立作答—反馈—下次验证”主线。结果页能区分原测记录、修订说明、学习练习和独立验证；原图不是所有学生都要先看的入口，只在核对时展开。

教师集中处理四件事：导入与核对、本次测评统计、待确认作答、复习进度。异常按“需要我做什么”分组，显示尚缺人数/题项和发布阻塞理由，避免要求教师读技术错误码。

移动端保留草稿、重复提交保护、清晰的保存/发布反馈和同 WebView 返回路径。宽度模拟只能证明布局，最终还需实际 Android 壳中验证登录返回、上传、图片放大、答题和断网重试。

## 8. 分析指标与教学试点

### 8.1 统计定义

| 指标 | 口径与限制 |
| --- | --- |
| 首测非空错误率 | 已确认 wrong / (correct + wrong)，只取指定发布版本的首次有效结果；blank 单列 |
| 首测空白率 | blank / (correct + wrong + blank)；不含缺失、pending、缺考和不纳入 |
| 历史独立表现 | 首测及 purpose=verify 的已确认作答；显示不同题数和总作答次数，重复作答不伪装成新题 |
| 到期验证完成率 | 指定日期应验证题项中完成已确认独立验证的比例；待确认单列，不提前计成功 |
| 本题巩固数 | 按既有三次有效验证计算；与整个知识点掌握程度分开 |
| 识别错误率 | 独立人工核对样本中，提取答案与人工真值不一致的比例；和判定错误率分开 |
| 复核负担 | 每批需人工处理题项比例、复核总耗时、教师每百项处理耗时 |

时间序列优先读取已有逐次事件，不为绘制曲线重复制造学习事实。缓存或快照需携带统计算法版本、发布版本和样本范围，并可从原事件重建。

近 7/30 天展示只描述观察；样本不足显示实际题数/次数和“证据不足”，不自动贴“已掌握”。同一道题反复正确与多道新题迁移正确分别呈现。

### 8.2 真实试点

选择一个班级、一次真实周测，先沿用教师当前确认方式建立对照记录，再经过新导入、预览、复核和发布。观察至少两轮周测及 2—3 周复习；具体日期随教学安排确认。

记录教师准备/复核/纠错耗时、学生进入和完成到期任务比例、系统误判与修订数、独立验证表现。若加入教师选定的同知识点新题，可作为迁移表现补充，但不把小样本前后变化宣称为升级导致的教学提升。

## 9. 施工阶段与交付物

下列为单人开发的粗估有效工作日，不包含教师等待、内容签审和真实课堂观察，须在 U0 后重新估算；它们不是交付承诺。阶段按门禁推进，不以日期强行放行。

| 阶段 | 范围与交付 | 依赖及完成条件 | 粗估 |
| --- | --- | --- | --- |
| U0 基线与协议 | 核对现有无分数链路、内容验收遗留；确定输入 schema、状态表、迁移方案、脱敏夹具 | 当前能力/缺口清单与可复现实例；不重写旧计划 | 2—3 天 |
| U1 统一作答证据 | 批次、证据、判定日志、CSV 兼容、逐项预览、冲突与幂等；无分数判定服务 | 两种输入经过相同服务，待确认不能发布 | 4—6 天 |
| U2 可追溯纠错与课堂闭环 | 修订入口、影响预览、有效结果视图、错题撤销、统计/复习回放 | 一条误判从发布到更正全过程可恢复、可解释；真实班级试用 | 4—6 天 |
| U3 选择题扫描 | 一个固定模板、题区定位、OMR、异常队列、抽检、任务恢复 | 按模板样本通过识别和绑定质量验收；不把依赖安装算交付 | 5—8 天 |
| U4 填空增强 | 单位、容差、别名、安全表达式；可选 AI 建议 | 物理正反例通过；AI 不直接写正式结果 | 4—7 天 |
| U5 后续探索 | 主观题纸面复习、拍照作答、细分能力证据；外部系统接入 | 另立范围与验收，不阻断 U1/U2 使用 | 不估算 |

**第一批可交付范围为 U0—U2，约 10—15 个有效工作日；此后先看真实使用再安排扫描投入。** U3/U4 的先后可按教师实际复核负担调整，但不能跳过 U1/U2 的证据与纠错基础。

建议代码职责：

- `learning.py` 保留 API 兼容与编排；将导入、判定、修订分别抽到小型领域模块，避免继续扩张单个分支函数。
- `grading.py` 的历史评分接口保持兼容隔离，新 outcome 服务不暴露 score。
- `learning_views.py`、`assets/learning.js` 增加预览差异、证据查看与纠错流程。
- `ocr.py` 继续做适配；新增 OMR/答题卡模板组件及其真实夹具。
- `question_content.py` 和已有版本化文档继续负责题目内容，不复制另一套题目渲染。
- 在 `tests/test_learning.py` 之外按新领域增加导入、修订、扫描质量测试；避免只断言接口 200。

## 10. 验收清单

以下全部是**待实施/待验收**的目标，不是本次测试结果。每项记录环境、时间、提交 SHA、实际结果和证据位置。

| 编号 | 场景 | 通过要求 |
| --- | --- | --- |
| A01 | 仅答案导入 vs 答案+外部结果导入 | 同一事实得到相同有效结果，来源各自保留 |
| A02 | 同名、跨班、未知学生、越权学校 | 阻断错绑/越权，不自动建账号或调整正式班级 |
| A03 | 原题号与小问映射 | 同时显示原卷号与录入序号，乱序输入仍准确，未知号明确报错 |
| A04 | 空白、缺失、缺考、不纳入 | 四种情形可区分，缺失阻断发布，后两者不入错题 |
| A05 | 单选、多选、非法选项 | 单选正确性与多选完全匹配符合口径；异常不猜测 |
| A06 | 外部判定冲突与规则未确认 | 冲突可定位；无最终依据不得发布 |
| A07 | 重复/并发/预览后修改 | 同请求幂等、异内容冲突；名单或规则变化不能复用旧预览 |
| A08 | 发布及重做 | 首次答案与标签冻结，重做不覆盖；学习练习不增加验证进度 |
| A09 | 已发布误判纠错 | 原记录仍可查；有效结果、统计和到期任务一致；原练习记录保留 |
| A10 | 同题多来源与规则修订 | 撤销一个来源不抹除其他有效来源；不静默改判历史练习 |
| A11 | 图片与批次隔离 | 学生不能访问他人答题卡；原件/题区定位可追溯；答案未开放不泄露 |
| A12 | 扫描错模板、偏移、擦改、缺页 | 进入异常，不把系统识别失败变成学生错误 |
| A13 | 填空物理边界 | 单位、量纲、符号、精度、表达式边界有正反例；未知进入 pending |
| A14 | 工作进程中断和重试 | 重启后可恢复，无重复发布或孤立有效判定；取消/超时有明确状态 |
| A15 | 数据迁移与回滚 | 生产副本中身份、首次作答、快照、历史练习保留；完整性与外键检查通过 |
| A16 | 教师与学生真实入口 | 教师完成导入—复核—发布—纠错，学生完成到期练习；真实 Android WebView 单列结果 |

扫描试点建议使用一个模板至少 50 张脱敏真实卡、合计不少于 1000 个选择题作答单元，覆盖倾斜、淡涂、擦改、多涂和空白。独立人工真值与开发调参样本分开；高置信通过项也在盲核范围内。以下是试点建议门槛，须 U0 确认：

- 验收样本中学生身份与题号绑定错误为 0；任一错绑即阻断该模板上线。
- 自动通过样本的答案提取准确率目标不低于 99.5%，同时报告自动通过数量、覆盖率和人工复核率，避免靠全部送人工“达标”。
- 初期人工复核率目标不高于 20%，不能以降低质量门槛换取；未达到时继续辅助模式。
- 教师完成复核后，验收集发布结果与确认真值一致；该样本结论不代表所有未来答题卡零错误。
- 记录 50 张卡的实际总耗时、排队时间和资源峰值；未测前不承诺固定处理秒数。

## 11. 发布、数据保护与回滚

只在后续实施发布时执行本节；本次文档编写不运行迁移或部署。

1. 对 `data/school.sqlite3` 做 SQLite 一致性备份，并备份原答题卡、文档与关联资源；核对 hash、空间和可恢复性。不能仅备份数据库而遗漏图片。
2. 在隔离生产副本执行可重复迁移。历史缺少置信度/来源不得补造；标记 legacy 并保留现有已确认结论。
3. 首批新投影以影子方式与现有结果对账，核对人数、作答、错题、练习及标签快照。任何差异必须解释，不能靠重建学生数据消除。
4. 按学校/测评灰度启用，切换一个统一读路径；迁移失败事务回滚，支持关闭新入口保留既有 CSV 使用。
5. 若新版本已接收学习记录，回滚应用时保留新增事件并准备向前修复；不得直接恢复旧库丢失发布后的作答。
6. 本地执行 `VERIFY_TARGET=local bash scripts/hsp_release_check.sh`；发布后执行 `REQUIRE_REMOTE_HEAD_MATCH=1 bash scripts/hsp_release_check.sh`，另验真实入口、学校数据库配置、任务执行和识别质量。
7. 远端 checkout 一致不等于进程已加载新代码；记录 app/worker、HTTP/runtime 与实际用户流程证据。门禁失败不能标“远端已验证”。

学生答案和扫描材料走有权限控制的资源接口。调用外部 AI 时使用最小题区与答案上下文，去除姓名、学号等无关身份信息；受学校配置、访问审计与用量限制控制。原图、日志及导出中的身份数据不进入公开仓库。

## 12. 与已有计划衔接及开工清单

本方案不替代[整卷导题设计](../specs/2026-09-28-document-first-question-ingestion.md)、[整卷导题实施计划](2026-09-28-document-first-question-ingestion-implementation.md)及其[验收记录](2026-09-28-document-ingestion-acceptance.md)。输入链路分为两条：原卷形成可靠题目，答题卡形成可靠学生答案；前者的 MinerU 能力不能代替后者的学生绑定和填涂识别。

既有验收记录中的教师真实 SSO 工作流、真实试卷内容签审、历史题映射/修复等事项，应在 U0 对照最新提交和证据确认是否关闭。不能引用旧验收文档中某次状态覆盖 10 月 1 日之后的新实现，也不能因为已有代码便视为通过。

开工先完成以下具体任务：

1. 从现有 CSV、旧历史记录及一批脱敏答题卡建立兼容样本与异常样本，不写生产记录。
2. 定稿来源协议、外部结果采用矩阵、修订事件和有效结果读取规范。
3. 绘制一个教师导入预览、一个冲突复核、一个发布后纠错页面，并贯通服务层验收样例。
4. U1/U2 完成后先跑一次真实班级周测—复习闭环，再决定是否进入 U3。

可在 U0 默认采用而不阻断方案的实施选择：CSV 优先、无分数、AI 仅建议、主观题后置。首次扫描模板、实际试点班级与日期、外部阅卷系统格式、识别门槛和资源保留期需在相应阶段开工前确认。
